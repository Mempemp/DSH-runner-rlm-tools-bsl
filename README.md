# dsh-rlm-tools-bsl

**rlm-tools-bsl живёт ровно столько, сколько работает DeepSeek Harness.**

Плагин DSH: поднимает MCP-сервер [rlm-tools-bsl](https://github.com/Dach-Coin/rlm-tools-bsl) (токен-эффективный анализ кодовых баз 1С) при старте DSH, гасит его вместе с DSH и показывает состояние сервера во вкладке настроек. Никакой службы Windows, никакого автозапуска «навсегда» и никакого ручного `run.bat`: закрыли DSH — сервер остановлен.

## Возможности

### 🔁 Сервер поднимается и гаснет вместе с DSH
При старте DSH плагин запускает `rlm-tools-bsl --transport streamable-http` на локальном порту (по умолчанию **9330**) и ждёт готовности по MCP-рукопожатию. При остановке DSH процесс гасится целым деревом (uv-трамплин → python → uvicorn), так что порт освобождается.

### ⚙️ Вкладка «rlm-tools-bsl» в настройках DSH
Секция в Settings: статус (работает процесс плагина / подхвачен внешний / остановлен / порт занят / ошибка), версия, pid, время работы, кнопки **Запустить / Остановить / Перезапустить**, настройки запуска и хвост лога процесса.

### 🔎 Подхват уже запущенного сервера и takeover
Если сервер уже отвечает на порту (остался от прошлой сессии), плагин не поднимает второй, а подхватывает существующий — и всё равно гасит его при выходе DSH (сервер на нашем порту считается своим; поведение отключается галочкой). Отличает «свой» сервер от чужого по MCP-рукопожатию: `/health` отдаёт generic `{"status":"ok"}`, а имя и версию знает только `initialize`.

### 🚧 Чужой процесс на порту — видно и разбираемо
Если порт занят посторонним приложением, вкладка показывает, кто именно (имя процесса и pid) и даёт кнопку **«Освободить порт»** — она завершает чужой процесс только по явному подтверждению, никогда автоматически.

### 🗂 Готовый JSON для подключения к DSH
Во вкладке есть блок «Подключение к DSH» с готовым JSON под MCP-менеджер и кнопкой «Скопировать»; ниже — те же данные. MCP-подключение плагин **не делает сам**: сервер к DSH подключается штатным MCP-механизмом DSH.

### 📁 Portable-режим через переменные окружения
Поля «Дополнительные аргументы», «Переменные окружения» и «Рабочий каталог» позволяют унести конфиги и индексы внутрь своей папки (`RLM_CONFIG_FILE`, `RLM_INDEX_DIR`) — сервер и его данные можно переносить между машинами как папку.

### 🔌 Роуты `/rlm/*` для других плагинов и агентов
`GET /rlm/state` отдаёт состояние сервера и действующие настройки, `GET /rlm/log?tail=N` — хвост лога, `GET /rlm/detect` — найденный путь к исполняемому файлу.

## Как подключить сервер к DSH (MCP)

Плагин отвечает только за процесс. Чтобы инструменты rlm появились у агента, добавьте сервер в MCP-менеджер DSH — один раз.

**Способ 1 — через UI (рекомендуется).** Settings → **MCP Server Manager** → **Add** → транспорт `streamable-http`, имя `rlm`, URL:

```
http://127.0.0.1:9330/mcp
```

**Способ 2 — строкой в файл** `~/.dsh/mcp-servers.json` (файл горячо перечитывается, перезапуск не нужен):

```json
{
  "serverName": "rlm",
  "transport": "streamable-http",
  "url": "http://127.0.0.1:9330/mcp",
  "enabled": true
}
```

Это элемент массива `servers` того же файла; если файл уже есть, добавьте объект в массив. Целиком для пустого файла:

```json
{
  "version": 1,
  "servers": [
    {
      "serverName": "rlm",
      "transport": "streamable-http",
      "url": "http://127.0.0.1:9330/mcp",
      "enabled": true
    }
  ]
}
```

Имя `rlm` даёт инструменты `mcp__rlm__rlm_start`, `mcp__rlm__rlm_execute`, `mcp__rlm__rlm_help`, `mcp__rlm__rlm_projects`, `mcp__rlm__rlm_index`, `mcp__rlm__rlm_end`.

> Порт в URL должен совпадать с портом из настроек вкладки (по умолчанию 9330).

**Способ 3 — статическая строка профиля** (если MCP-менеджер не используется) — в `~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
- insert:
    - id: mcp-rlm
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: rlm
        transport: streamable-http
        url: http://127.0.0.1:9330/mcp
```

Способы 1 и 3 не комбинируйте: два MCP-сервера с одинаковым `serverName` конфликтуют.

## Установка

Нужны `dsh` ≥ 0.1.2-rc.1 и установленный `rlm-tools-bsl` (ниже). Ставится тремя способами — результат один и тот же.

**Из релиза** (скачивать ничего не нужно):

```sh
dsh plugin --profile web add https://github.com/Mempemp/DSH-runner-rlm-tools-bsl/releases/download/v0.1.0/dsh-rlm-tools-bsl-0.1.0.tgz
```

**Локальный архив** `dsh-rlm-tools-bsl-0.1.0.tgz` (скачан со страницы релизов или собран самому: `cd dsh-rlm-tools-bsl && npm pack`):

```sh
dsh plugin --profile web add dsh-rlm-tools-bsl-0.1.0.tgz
```

**Папка плагина** (режим разработки, правки в `lib/*.js` подхватываются без переустановки):

```sh
dsh plugin --profile web add <путь к папке>/dsh-rlm-tools-bsl
```

После установки перезапустите DSH (композиция плагинов читается на старте) и обновите страницу в браузере.

### Установка самого rlm-tools-bsl

Python 3.10+ и [uv](https://github.com/astral-sh/uv):

```sh
uv tool install rlm-tools-bsl
```

Это «portable-подобный» вариант: изолированное окружение uv, исполняемый файл в `%USERPROFILE%\.local\bin\rlm-tools-bsl.exe`, никаких служб и системных изменений. Плагин находит файл сам (кнопка **«Определить»** во вкладке), либо укажите путь руками.

> **Службу Windows (`simple-install-from-pip.ps1`) ставить НЕ нужно** — она запускала бы сервер постоянно, что противоречит смыслу плагина. Если служба уже стоит, остановите её: `rlm-tools-bsl service stop` (или `net stop <имя службы>`), иначе она будет держать свой порт.

Обновление: `uv tool upgrade rlm-tools-bsl`, затем **Перезапустить** во вкладке.

### Если `dsh` не в PATH

Локальная установка и DSH Desktop не добавляют `dsh` в `PATH` — вызывайте точку входа через node. Путь к `bin.js`:

| Как установлен DSH | Путь к `bin.js` |
|---|---|
| локально (`npm install @deepseek-ai/dsh`) | `<папка установки>\node_modules\@deepseek-ai\dsh\lib\bin.js` |
| DSH Desktop | `%LOCALAPPDATA%\Programs\DSH Desktop\resources\app\node_modules\@deepseek-ai\dsh\lib\bin.js` |

```powershell
node "C:\путь\к\dsh\lib\bin.js" plugin --profile web add "C:\путь\к\dsh-rlm-tools-bsl-0.1.0.tgz"
```

### Возможные сложности

| Симптом | Что делать |
|---|---|
| `ERR_PNPM_UNEXPECTED_STORE` | добавить `--store-dir="<путь к вашему pnpm store>"` к команде установки |
| `EPERM` при записи в `…\profiles\web` | нет прав на папку профиля (песочница, антивирус): закрыть DSH, разрешить запись, повторить |
| Предупреждения про peer-зависимости (`cordis`, `react`, `react-dom`) | игнорировать: внешних зависимостей у плагина нет, react приходит из рантайма DSH |
| Путь к архиву содержит пробелы | ломается на `.cmd`-шиме pnpm — положите архив в путь без пробелов или поставьте папкой |
| После установки в `dsh.profile.bundles` появились лишние пакеты | `dsh plugin add` перезаписывает список слоёв: плагины, которые `dshmarket` держал «горячими» (`.dsh-market\hot-*.yml`), получают постоянную активацию. Ненужные строки можно удалить из `package.json` профиля, на работу плагина это не влияет |
| Вкладки нет после установки | DSH не перезапущен либо страница не перезагружена жёстко (`Ctrl+Shift+R`) |
| Статус «порт занят» | порт держит другой процесс (например, служба rlm-tools-bsl или чужое приложение) — во вкладке видно имя и pid, есть кнопка «Освободить порт»; либо смените порт в настройках |

Проверка, что хост-часть поднялась: `curl -s http://127.0.0.1:<порт>/rlm/state` — должен вернуться JSON с состоянием сервера.

## Параметры

| Поле вкладки | Ключ в JSON | Значение по умолчанию |
|---|---|---|
| Исполняемый файл | `command` | найденный `rlm-tools-bsl` (PATH → `%USERPROFILE%\.local\bin`) |
| Порт | `port` | `9330` |
| Хост | `host` | `127.0.0.1` |
| Дополнительные аргументы | `extraArgs` | пусто |
| Рабочий каталог | `cwd` | `$DSH_HOME/rlm-tools-bsl` (отсюда читается `.env`) |
| Переменные окружения | `env` | пусто |
| Поднимать при старте DSH | `autoStart` | `true` |
| Гасить вместе с DSH даже подхваченный процесс | `takeover` | `true` |

Настройки лежат на машину: `$DSH_HOME/rlm-tools-bsl/settings.json` (`$DSH_HOME` — переменная окружения, иначе `~/.dsh`). Значения можно задать и строкой плагина в `cordis.patch.yml` профиля — приоритет у сохранённых во вкладке.

Почему порт 9330, а не 9000 по умолчанию у самого rlm-tools-bsl: 9000 часто занят (Docker-сервисы, Lemonade и другие локальные серверы). Порт можно изменить во вкладке.

## Использование

1. Установите плагин и `rlm-tools-bsl`, добавьте MCP-сервер (см. раздел «Как подключить сервер к DSH»).
2. Перезапустите DSH — в Settings появится вкладка **«rlm-tools-bsl»**, сервер поднимется автоматически.
3. Проверьте статус: «работает — процесс плагина (pid …)» и версию. Если ошибка — хвост лога на той же вкладке.
4. Закройте DSH — сервер остановлен (порт освобождён). Плагин общего назначения: MCP-менеджер сам переподключится при следующем старте.

## Требования

- DeepSeek Harness (`dsh web` или DSH Desktop) ≥ 0.1.2-rc.1 — вкладка использует слот `settings.section`
- Node.js ≥ 20
- [rlm-tools-bsl](https://github.com/Dach-Coin/rlm-tools-bsl) ≥ 1.35 (Python 3.10+, ставится через uv) — отдельно, плагин его не устанавливает

## HTTP-роуты

| Метод и путь | Назначение |
|---|---|
| `GET /rlm/state` | состояние сервера, действующие настройки, пути, хвост лога |
| `GET /rlm/log?tail=N` | хвост лога процесса (по умолчанию 200 строк, максимум 500) |
| `GET /rlm/detect` | найденный в системе путь к `rlm-tools-bsl` |
| `POST /rlm/start` | запустить сервер (или подхватить уже запущенный) |
| `POST /rlm/stop` | остановить сервер (включая подхваченный, если включён takeover) |
| `POST /rlm/restart` | перезапустить |
| `POST /rlm/save` | `{settings}` — сохранить настройки запуска |
| `POST /rlm/free-port` | `{pid}` — завершить чужой процесс, держащий порт |

## Структура репозитория

- `dsh-rlm-tools-bsl/lib/index.js` — host-часть (ESM): жизненный цикл процесса, пробы готовности, роуты `/rlm/*`.
- `dsh-rlm-tools-bsl/lib/client.js` — клиентская часть: секция `settings.section` («rlm-tools-bsl») со статусом, управлением, настройками, сниппетом MCP и логом.
- `dsh-rlm-tools-bsl/cordis.patch.yml` — строка монтирования плагина в композицию профиля.
- `dsh-rlm-tools-bsl/tests/_http.mjs` — E2E хост-части без DSH: мок `ctx.webServer` + реальный сервер rlm-tools-bsl (`node tests/_http.mjs`).
- `dsh-rlm-tools-bsl/README.md` — описание пакета (то же, что и в архиве релиза).

Внешних зависимостей нет: только `node:*` и React из рантайма DSH.

## Безопасность

- Сервер `rlm-tools-bsl` слушает `127.0.0.1` — наружу не выходит; плагин не подставляет `0.0.0.0`.
- Хост-роуты доступны локально без токена сессии (как и роуты других плагинов через `ctx.webServer.register`) — не выставляйте DSH в сеть без токена.
- Кнопка «Освободить порт» завершает процесс только по явному подтверждению и только тот, который держит настроенный порт.
- Роут `GET /rlm/state` отдаёт значения переменных окружения как есть — не храните в них секреты, если машина не доверенная.
