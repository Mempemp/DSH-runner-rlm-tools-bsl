# dsh-rlm-tools-bsl v0.1.0

Первый выпуск: MCP-сервер **rlm-tools-bsl** поднимается вместе с DSH и гасится вместе с ним.

## Возможности

- **Жизненный цикл вместе с DSH** — сервер стартует при запуске DSH (после MCP-рукопожатия) и завершается деревом процессов при остановке DSH; порт освобождается; служба Windows не регистрируется.
- **Вкладка «rlm-tools-bsl»** — статус, версия, pid, кнопка «Перезапустить», поле порта и готовый JSON для MCP-менеджера с кнопкой «Скопировать»; при ошибке — текст и хвост лога.
- **Подхват внешнего процесса и takeover** — если сервер уже отвечает на порту, второй не поднимается, а существующий гасится при выходе DSH (отличает свой сервер от чужого по MCP-рукопожатию: `/health` у rlm-tools-bsl отдаёт generic `{"status":"ok"}`).
- **Диагностика занятого порта** — видно имя и pid чужого процесса; чужие процессы плагин никогда не завершает.
- **Продвинутые параметры** — `command`, `env` (`RLM_CONFIG_FILE`, `RLM_INDEX_DIR` — portable-конфиги), `takeover`, `port` задаются строкой плагина в `cordis.patch.yml`; в UI вынесен только порт.
- **Роуты `/rlm/*`** — состояние, лог, запуск/остановка/перезапуск, сохранение порта.

## Прочее

- Внешних зависимостей нет: host-часть на `node:*`, клиентская — на React из профиля DSH.
- Порт по умолчанию — 9330 (у самого rlm-tools-bsl 9000, который часто занят).
- Подключение к DSH — штатным MCP-механизмом (`dsh-mcp-manager` или строка `@deepseek-ai/dsh-mcp-client` в профиле); инструменты: `mcp__rlm__rlm_start`, `mcp__rlm__rlm_execute`, `mcp__rlm__rlm_help`, `mcp__rlm__rlm_projects`, `mcp__rlm__rlm_index`, `mcp__rlm__rlm_end`.
- Требуется dsh ≥ 0.1.2-rc.1 (слот `settings.section`) и установленный `rlm-tools-bsl` (Python 3.10+, `uv tool install rlm-tools-bsl`); подходит и `dsh web`, и DSH Desktop.
- E2E хост-части без DSH: `node dsh-rlm-tools-bsl/tests/_http.mjs` — мок `ctx.webServer` и настоящий сервер rlm-tools-bsl (24 проверки жизненного цикла).
