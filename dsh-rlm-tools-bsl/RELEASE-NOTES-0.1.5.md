# dsh-rlm-tools-bsl v0.1.5

Запись сервера уходит туда, куда смотрит менеджер MCP: с 0.2.5 он держит список в своей папке.

## Изменения

- **Автопрописка в менеджер 0.2.5 и новее** — `@wingsky-1/dsh-mcp-manager` с 0.2.5 читает
  `$DSH_HOME/@wingsky-1/dsh-mcp-manager/mcp.json`, а `$DSH_HOME/dsh-mcp.json` остался от версий до 0.2.5:
  его менеджер переносит в новое место один раз и убирает. Плагин писал в старый файл, поэтому сервер
  поднимался и работал, а в панели MCP его не было. Теперь файл выбирается по раскладке менеджера:
  своя папка или её файл — актуальная раскладка, оставшийся файл-предшественник — старая, иначе по версии
  установленного пакета (граница — 0.2.5).
- **Тест раскладок без установленного rlm-tools-bsl** — `node tests/_mcp-store.mjs`: заглушка MCP-сервера
  на порту сценария, четыре случая (актуальное хранилище рядом с оставшимся файлом, только файл-предшественник,
  свежая установка 0.2.7, установленный 0.2.4). Ни одного скачивания и ни одного реального процесса сервера.
- **README** — таблица хранилищ дополнена актуальным путём и пояснением, почему запись в старый файл до панели
  не доходит.

## Прочее

- E2E хост-части: 31 проверка (`node dsh-rlm-tools-bsl/tests/_http.mjs`); раздел автопрописки перенастроен на
  хранилище менеджера 0.2.5+.
- Требуется dsh ≥ 0.1.2-rc.1 и Node.js ≥ 20.
